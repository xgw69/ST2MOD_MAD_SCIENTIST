# 回归验证

```sh
dotnet run --project tests/CombatRegression
python tests/validate_resources.py
```

`CombatRegression` 直接编译生产代码中的融合模型、效果上下文、科学传承、炼制和 X 费生成卡，使用小型游戏接口替身运行，不需要安装游戏。替身刻意保留浅复制、Owner 禁止重复赋值、费用/关键词延迟初始化、生成卡需显式注册等约束；Harmony 使用真实 NuGet 包。

目前有 26 项断言：材料隔离及再次融合、循环拒绝、费用/类型/目标/关键词/重放、序列化、X 值传递与恢复、异常清理、并发玩家上下文、九种选择的战斗注册、战后药水奖励和零能量升级 X 射线。资源脚本另有 4 项检查，覆盖中英词条变量、翻译键、动画路径和部署路径。

这些检查不证明目标游戏版本的二进制 API 兼容性，也不替代 Godot、奖励 UI、存档重连或联机实测。接口替身没有复制完整的游戏引擎、战斗钩子、存档编码或 UI 行为。

## 目标客户端验收

1. 使用实际安装的 `sts2.dll` / `0Harmony.dll`、Godot SDK 4.5.1、BaseLib 3.4.7 构建。`dotnet build -c Release -p:ModsPath=<临时部署目录>`；分别检查 ModsPath 有/无末尾分隔符时，DLL、JSON、PDB、PCK 都在同一个 MadScientist 子目录。
2. 使用 `tools/test_headless.ps1` 验证启动、资源和动画路径。脚本使用独立日志，仅在最终成功标记出现且没有 Mod 错误时通过。这只是启动检查。
3. 科学传承逐一选择九种形态并打出；疯狂科学家生成攻/技/能各一张；爆破装置、伦理边界、疯狂科研生成的牌都能正常打出。
4. 同一战斗连续融合 A+B、C+D，再把成品融合；检查前一张内容不变。覆盖单攻+防御、单攻+群攻、两张不可打出组件、攻击组件+攻击、消耗/保留、升级减费、X 费、禁忌科学+X 费。检查只计一次出牌，重放/消耗作用于整体，首段击杀目标后不会对死亡目标再次执行单攻。
5. “处理”在无牌可抽时不得取走旧手牌；正常抽牌时仅融合实际抽到的牌。“组装”只有一个组件和“大融合”只有一张手牌时也能融合。
6. 两张执迷不误同时在手时，两张都允许打出；其他技能受限，离手后限制消失。该行为依据设计文档已确认的 Q8，并同步了中英文案。
7. 升级 X 射线在零能量时攻击一次；突击根据实际未格挡伤害回能量；全自动运行按伤害结果中的目标去重计数，包含已被击杀的敌人。
8. 炼制记录最左侧药水；空药水栏无奖励。记录后喝掉/丢弃原药水、药水栏满、重复使用/重放炼制、两位玩家同时使用，均检查战后奖励的类型、数量及归属。失败战斗不应出现奖励。
9. 验证升级卡牌的中英文数字；升级科学方法/伪科学方法不再消耗。
10. 观察待机、攻击、施法、受击、死亡、胜利、缩小/变大效果以及联机角色的贴图、血条/意图位置；动画结束应恢复待机，不出现基础尺寸跳变。
11. 两端使用完全一致的游戏、BaseLib、DLL 和 PCK，验证随机科研/随机目标一致、融合牌的重连及存档还原。融合对其他 Mod 卡牌采用效果调用适配层；这类卡的特殊牌堆依赖还需逐张检查。
